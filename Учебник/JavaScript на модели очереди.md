# JavaScript на модели очереди
[[Учебник QA|Все статьи]] · Предыдущая: [[Web и API через состояние боя]] · Далее: [[SQL на бестиарии GRUNTWORK]]

**До начала:** [[Состояния и таблицы решений]]. **Цель:** прочитать небольшую функцию и связать её ветви с тестами. **Время:** 60–90 минут. HTTP для запуска не требуется.

## Подготовка
Нужен Node.js с поддержкой встроенного node:test. В PowerShell перейди в корень QA-Stading и выполни:
```powershell
node --version
node --test labs/encounter.test.mjs
```
Если node не найден, вернись к ручным таблицам: установка среды — отдельная задача. Команда запускает учебные тесты, не настоящий RPG Codex.

## Значения и переменные
```js
const participants = ["Крыса", "Стражник", "Контрабандист"];
let activeIndex = 0;
const round = 1;
```
const запрещает переназначить переменную, но не делает массив неизменяемым. let позволяет присвоить новое значение. Строки заключены в кавычки, числа — нет. Массив хранит упорядоченные элементы, индекс первого равен нулю.

Состояние удобно объединить в объект:
```js
const state = { participants, activeIndex, round };
```
Поля объекта — именованные значения. state.round читает номер раунда.

## Разбираем переход
В файле labs/encounter.mjs функция advance принимает состояние и роль. Сначала проверяет условия, затем вычисляет новый индекс.
```js
const nextIndex = (state.activeIndex + 1) % state.participants.length;
const nextRound = state.round + (nextIndex === 0 ? 1 : 0);
```
Оператор % возвращает остаток. Для длины 3 получаем: 1 % 3 → 1, 2 % 3 → 2, 3 % 3 → 0. Пустой список отсекается заранее, потому что остаток от деления на ноль даёт NaN.

=== сравнивает без приведения типов. Условное выражение «условие ? значениеДа : значениеНет» добавляет один при возврате к началу.

## Проверка должна уметь падать
В labs/encounter.test.mjs assert.deepEqual сравнивает структуру результата с ожиданием. Если просто вызвать функцию без assert, отсутствие исключения ещё не подтвердит правильный раунд.

Запусти исходный набор. Затем в отдельной рабочей ветке замени % на + в расчёте nextIndex и снова запусти проверки. Это намеренное повреждение учебного кода: тест конца очереди должен обнаружить нарушение. После эксперимента верни исходную формулу вручную.

## Попробуй
Добавь собственный тест для очереди из четырёх участников и старта с последнего индекса. До запуска запиши ожидаемый результат. Затем добавь тест трёх последовательных переходов.

> [!tip]- Самопроверка
> Четыре участника, индекс 3, раунд 5 → индекс 0, раунд 6. Тест последовательности должен проверять промежуточные результаты либо явно фиксировать конечный и область покрытия.

Готовность: можешь объяснить каждую строку своего теста. Исходники: [MDN — грамматика и типы](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Grammar_and_types). Далее: [[Автоматизация без слепого копирования]].
