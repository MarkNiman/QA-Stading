# Тестовая документация на одном примере
[[Учебник QA|Все статьи]] · Предыдущая: [[Как читать требования и задавать вопросы]] · Далее: [[Тест-дизайн через границы и классы]]

**До начала:** [[Как читать требования и задавать вопросы]]. **Цель:** выбрать подходящую форму записи и составить воспроизводимый отчёт. **Время:** 45–60 минут.

## Один сюжет, разные документы
Для RPG Codex чек-лист перечисляет проверки очереди; тест-кейс подробно описывает одну; баг-репорт сообщает конкретное расхождение; отчёт о прогоне показывает охват и ограничения. Каждый документ отвечает на свой вопрос.

## Разобранный тест-кейс
Это пример по модели C1, а не результат проверки настоящего приложения.

| Поле | Пример |
|---|---|
| ID | DEMO-TC-END |
| Требование | C1, переход после последнего |
| Предусловия | gm; три участника; активный индекс 2; раунд 4 |
| Данные | Крыса, Стражник, Контрабандист |
| Шаг | Выполнить одно переключение |
| Ожидание | Индекс 0, раунд 5, прежний состав и порядок |
| Факт | Не выполнялось |
| Статус | NOT RUN |

Важно фиксировать не только переход, но и то, что не должно измениться. Это помогает обнаружить случайную перестановку участников.

## Пример баг-репорта
**Учебное вымышленное наблюдение:** «В конце очереди раунд увеличивается на два».
Предусловия и шаги — как в DEMO-TC-END. Ожидаемый раунд 5, наблюдаемый в вымышленном примере — 6. Влияние: счётчик длительности эффектов может стать неверным, если он связан с раундами; эту связь нужно проверить отдельно.

Хороший отчёт не утверждает «ошибка в цикле», если исходный код не исследован. Он описывает воспроизводимое поведение. Приложение к настоящему дефекту должно показывать исходное и конечное состояние, версию, роль и время.

## Что написать после прогона
Например: «Спроектированы четыре сценария C1. Выполнены два, оба PASS; два BLOCKED из-за недоступности второй роли. Проверка реального API не проводилась». Это только образец формулировки, а не выполненная работа.

Отчёт «100% PASS» без числа проверок и объёма покрытия скрывает больше, чем сообщает. Статусы не заменяют описание границ исследования.

## Попробуй
Создай черновик чек-листа из четырёх пунктов для очереди. Выбери самый рискованный и распиши тест-кейс. Затем напиши баг-репорт по вымышленному наблюдению: активность перешла верно, но состав очереди изменился.

> [!tip]- Самопроверка
> Сохрани первоначальный порядок в предусловиях. В факте покажи новый порядок. Назови отчёт учебным; не регистрируй его как обнаруженный дефект RPG Codex.

Формы: [[Шаблон чек-листа]], [[Шаблон тест-кейса]], [[Шаблон баг-репорта]]. Готовность: коллега может повторить проверку без устных пояснений.
