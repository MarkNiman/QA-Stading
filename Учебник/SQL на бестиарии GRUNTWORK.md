# SQL на бестиарии GRUNTWORK
[[Учебник QA|Все статьи]] · Предыдущая: [[JavaScript на модели очереди]] · Далее: [[Автоматизация без слепого копирования]]

**До начала:** умение читать таблицы. **Цель:** получить строки по условию и найти отсутствующие связи. **Время:** 45–60 минут.

## Зачем QA база данных
Интерфейс может показывать правильное имя существа, но сохранять неправильную фракцию. Запрос помогает исследовать данные. Чтобы признать дефект приложения, нужно ещё знать схему, правила и момент сохранения.

Для лаборатории используем отдельную базу в памяти. Это учебный бестиарий GRUNTWORK с вымышленными записями; реальная БД проекта не нужна.

## Две связанные таблицы
creatures хранит существ: id, name, kind, faction_id. factions хранит фракции: id и name. Идентификатор связывает записи, даже если у двух фракций одинаковые названия.

Данные и запросы находятся в labs/bestiary.sql. Выполни из корня:
```powershell
python labs/check_bestiary.py
```
Скрипт использует стандартный sqlite3, создаёт базу в памяти и проверяет учебные результаты. Установка отдельного сервера не требуется.

## Отберём гуманоидов
```sql
SELECT name
FROM creatures
WHERE kind = 'humanoid'
ORDER BY id;
```
SELECT выбирает столбец, FROM — таблицу, WHERE — условие, ORDER BY — порядок. Без ORDER BY порядок строк не гарантирован.

В наших данных результат: Стражник, Контрабандист, Бандит. Запрос ничего не сообщает о том, правильно ли дизайнер назначил им тип: это другой источник ожидания.

## Соединим существ с фракциями
```sql
SELECT c.name, f.name AS faction
FROM creatures AS c
LEFT JOIN factions AS f ON f.id = c.faction_id
ORDER BY c.id;
```
c и f — короткие имена таблиц. LEFT JOIN сохраняет каждое существо, даже если справа нет совпадения. У Крысы faction_id равен NULL, поэтому название фракции тоже NULL.

Чтобы найти гуманоидов без связанной фракции, добавь до ORDER BY:
```sql
WHERE c.kind = 'humanoid' AND f.id IS NULL
```
Получишь Бандита: у него учебный faction_id 99, отсутствующий в factions. Это намеренно внесённая аномалия; ограничение внешнего ключа в лабораторной схеме не задано.

## Попробуй
Напиши запрос только для существ с существующей фракцией. Предскажи, кто исчезнет при замене LEFT JOIN на INNER JOIN.

> [!tip]- Самопроверка
> Останутся Стражник и Контрабандист. Крыса без фракции и Бандит с отсутствующей связью исчезнут. Сравнение с NULL через = не заменяет IS NULL.

Готовность: объясняешь, почему отсутствие строки после JOIN не означает отсутствие существа.
