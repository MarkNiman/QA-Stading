# Web и API через состояние боя
[[Учебник QA|Все статьи]] · Предыдущая: [[Состояния и таблицы решений]] · Далее: [[JavaScript на модели очереди]]

**До начала:** [[Состояния и таблицы решений]]. **Цель:** различать интерфейс, сетевой запрос и состояние сервера. **Время:** 45–60 минут.

## Что происходит после нажатия
В сетевом приложении интерфейс может отправить команду серверу, получить ответ и обновить экран. Это типичная схема, а не утверждение об архитектуре текущего RPG Codex. Перед практикой выясни, используется ли HTTP, WebSocket или другой механизм.

HTTP-запрос содержит метод, адрес, заголовки и иногда тело. Ответ содержит статус, заголовки и иногда тело. JSON — текстовый формат данных; число 2 и строка "2" в нём различаются.

## Разберём вымышленный контракт C2
Адрес ниже существует только в упражнении и не предлагается к запуску:
```http
POST /training/encounters/demo/advance
Content-Type: application/json

{"expectedVersion":7}
```
Роль определяется серверной сессией, а не полем role в теле запроса. При успехе возвращается:
```json
{"activeIndex":1,"round":1,"version":8}
```
В C2 ожидаем 200 при успехе, 403 для известной запрещённой роли и 409 при устаревшей версии. Это выбранные условия упражнения, не универсальная схема для любого API.

## Что проверять кроме статуса
Ответ 200 может содержать неправильный индекс, не увеличенную версию или прежнее состояние. Поэтому отдельно проверяй статус, форму данных, значения и фактическое сохранение. Для отказа — отсутствие изменения состояния.

Метод POST сам по себе не гарантирует защиту от повторной обработки. В C2 повтор команды с expectedVersion 7 после успеха должен получить 409 и не переключить ход ещё раз.

## Практика в DevTools
В запущенном учебном окружении RPG Codex открой DevTools, затем Network. Очисти список, выполни одно действие и найди связанный обмен. Запиши транспорт, метод или тип сообщения, обезличенный путь, статус и значимые поля.

Если HTTP-запроса нет, проверь WebSocket-сообщения. Отсутствие строки Fetch/XHR не доказывает, что сервер не участвовал. Не публикуй токены, cookies и реальные данные в wiki.

## Попробуй без сервера
Составь матрицу C2: gm с актуальной версией; player с актуальной; gm с устаревшей; повтор успешно обработанной команды. Укажи ожидаемое состояние после каждого случая.

> [!tip]- Самопроверка
> Успех увеличивает версию на один. Остальные случаи не меняют состояние; повтор со старой версией получает 409. При совмещении двух ошибок приоритет ответа должен быть задан контрактом — в C2 его пока нет.

Готовность: отличаешь UI-проверку от проверки серверного права. Источник: [MDN — обзор HTTP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Overview).
