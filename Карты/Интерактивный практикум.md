# Интерактивный практикум
Первый интерактивный модуль дополняет [[Учебник QA]], а не заменяет wiki. Пройди его до работы с настоящим [[RPG Codex]]. Нужен только обычный браузер, без Node.js, Python и сторонних плагинов Obsidian.

## Как открыть
1. Получи свежую копию репозитория. Если клонировал Git и нет незакоммиченных изменений: `git pull --ff-only`. Если есть свои изменения, сначала сохрани их; не используй reset/clean.
2. В проводнике открой папку `trainer` внутри хранилища.
3. Дважды нажми `index.html`. В браузере откроется «QA • Лаборатория решений».

[Файл тренажёра](../trainer/index.html). Если Obsidian показывает HTML как текст, открой файл через проводник и браузер. На GitHub HTML отображается как исходный код: скачай репозиторий через Code → Download ZIP, распакуй и открой файл локально. Отдельный сайт не опубликован.

## Маршрут на 60 минут
| Шаг | Что делаешь | Что должно остаться |
|---|---|---|
| 1. Правило → ожидание | Предсказываешь переход до запуска | Объяснение двух свойств результата |
| 2. Наблюдение → вывод | Проверяешь сборки A/B и эталон C1 | Найденное расхождение с условиями |
| 3. Границы | Выбираешь данные P1, получаешь обратную связь | Набор входов с причиной выбора |
| 4. Баг-репорт | Описываешь воспроизведение и скачиваешь Markdown | Собственный черновик для ревью |

Рекомендуемые статьи рядом: [[От игровой функции к проверке]], [[Как читать требования и задавать вопросы]], [[Тестовая документация на одном примере]], [[Тест-дизайн через границы и классы]].

## Как учиться, а не прокликивать
Сначала сформулируй ожидание своими словами. Если ответ неверный, объясни, какую часть контракта упустил. Не открывай подсказку до первой попытки. После успешной проверки назови случай, который она не покрывает.

В A/B ошибки созданы намеренно. Контракты: [[Учебные модели проектов]]. Счётчик браузера отмечает упражнения, а не профессиональную квалификацию. Проверка формы баг-репорта обнаруживает пустые разделы, но не оценивает истинность текста. [[Прогресс]] и [[Журнал обучения]] автоматически не меняются.

## Сохрани результат
- Кнопка «Скачать Markdown» сохраняет черновик. Перенеси его в `Практика` и свяжи с [[Интерактивный практикум]].
- Резервная копия JSON содержит прогресс и поля отчёта. Её можно восстановить после смены браузера или компьютера.
- Данные остаются в браузере, не уходят на сервер. Очистка данных браузера или смена пути файла может потерять локальный прогресс: скачивай резервную копию.
- Наблюдение стенда не сохраняется между перезагрузками. Перед закрытием вставь важное наблюдение в черновик.

## Перенос на настоящий проект
После модуля выполни [[QA-001 — Переключение ходов]]. Сначала проверь актуальные требования и версию стенда: контракт C1 не является доказательством его поведения. Учебные дефекты A/B не нужно регистрировать в настоящем проекте.

## Что пока не интерактивно
Это первый модуль: основы, очередь, границы и документация. API, SQL, JavaScript и CI остаются в статьях и `labs`; здесь не реализованы сервер, редактор SQL или запуск произвольного кода.
